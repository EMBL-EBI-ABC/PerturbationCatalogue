# LLM Pipeline — Perturbation-Aware Language Model

GSoC 2026 project: Building a Perturbation-Aware LLM for Multimodal In Silico Perturbation Modelling.

## Overview

This pipeline connects to the EMBL-EBI Perturbation Catalogue REST API and converts perturbation experiment data into instruction-tuning training records for fine-tuning a biomedical language model (BioMedLM).

## Prediction Tasks

For each modality, the model is trained to answer natural language queries given only information available at inference time:

**CRISPR screen**
- Input: perturbed gene, cell line
- Output: fitness class (essential / anti-essential / neutral) and effect summary

**scPerturb-seq DEA**
- Input: perturbed gene, cell line
- Output: top-k upregulated and downregulated genes with log2fc values (list format), or a single (perturbed gene, affected gene) pair with direction and log2fc (pairwise format — see `generate_dea_pairwise.py`)

**scPerturb-seq GSEA**
- Input: perturbed gene, cell line
- Output: top-k activated and suppressed biological pathways with NES scores

Note: dataset identifiers are not provided to the model at inference time. The model is expected to generalise across datasets given only the biological context.

## Pipeline

The pipeline consists of five steps: fetch, oversample (optional but recommended), split, fine-tune, evaluate.

### Step 1 — Fetch training data

Use `catalogue_api_new.py` / `prepare_training_data_new.py` (not the original `catalogue_api.py` / `prepare_training_data.py` — the API's field names changed after the originals were written; the `_new` versions are the current, correct ones).

```bash
# CRISPR screen
python prepare_training_data_new.py --modality crispr --dataset_id biogrid_5 --output data/crispr_biogrid5.jsonl

# scPerturb-seq DEA, list format (automatically saves data/genes.txt for the GSEA step)
python prepare_training_data_new.py --modality perturb_seq --dataset_id nadig_2025_hepg2 --output data/dea_nadig.jsonl

# scPerturb-seq DEA, pairwise format (one record per gene-affected-gene pair, all significant genes)
python generate_dea_pairwise.py --dataset_id nadig_2025_hepg2 --output data/dea_pairwise_nadig.jsonl

# scPerturb-seq GSEA (uses genes.txt generated by the DEA step above)
python prepare_training_data_new.py --modality gsea --dataset_id nadig_2025_hepg2 --genes_file data/genes.txt --output data/gsea_nadig.jsonl

# Combine all modalities into one corpus
cat data/crispr_biogrid5.jsonl data/dea_nadig.jsonl data/gsea_nadig.jsonl > data/full_corpus.jsonl
```

To exclude disease/condition from input fields (for ablation testing), add `--no_condition` to any of the above.

Datasets with many perturbations can return a very large number of raw rows — use `--max_records` to cap how many rows are fetched (default 5000). At least one dataset in this project (`nadig_2025_hepg2`) was confirmed to have over 30 million total raw rows via the API's `total_rows_count` field — check this for a dataset before fetching without a cap.

### Step 2 — Oversample (recommended for CRISPR class imbalance)

CRISPR fitness classes are naturally imbalanced (most genes are neutral, few are essential). `oversample_corpus.py` duplicates essential-class records before splitting so the model sees a more balanced signal during training.

```bash
python oversample_corpus.py --input data/full_corpus.jsonl --output data/full_corpus_oversampled.jsonl --oversample_factor 5
```

### Step 3 — Create gene-level splits

Standard split (fresh random gene-level assignment each run):

```bash
python pipeline.py split --corpus data/full_corpus_oversampled.jsonl --output_dir data/splits/
```

Pinned split (recommended when comparing multiple experiments): if you're running more than one experiment and want CRISPR/GSEA metrics to be directly comparable across runs, reuse a prior run's exact gene-level split for CRISPR/GSEA genes, and only freshly split genes that are new (e.g. from a different DEA record format or a new dataset):

```bash
python split_with_pinned_crispr_gsea.py \
    --corpus data/full_corpus_oversampled.jsonl \
    --reference_manifest runs/<prior_experiment>/split_manifest.json \
    --output_dir data/splits_pinned/
```

Without pinning, changing DEA's data between runs can silently reshuffle which CRISPR/GSEA genes land in train vs. test, making cross-experiment comparisons on those two modalities unreliable — even though their own training data never changed.

### Step 4 — Fine-tune

```bash
# Standard LoRA on BioMedLM
python finetune.py \
    --splits_dir data/splits/ \
    --output_dir runs/exp_001/ \
    --model_name stanford-crfm/BioMedLM \
    --epochs 3 --batch_size 4 --grad_accum 4 --lr 2e-4

# QLoRA for memory-constrained environments
python finetune.py \
    --splits_dir data/splits/ \
    --output_dir runs/exp_001/ \
    --use_qlora
```

For anything beyond a very small corpus, run this on a GPU cluster rather than locally — a single A100 or H200 GPU is sufficient for LoRA fine-tuning BioMedLM at the corpus sizes used in this project. If running on a SLURM-managed cluster, submit as a batch job (`sbatch`) with `--gres=gpu:1` (or the equivalent GPU resource flag for your cluster) rather than running interactively.

### Step 5 — Evaluate

```bash
python evaluate.py \
    --adapter_dir runs/exp_001/final_adapter/ \
    --splits_dir data/splits/ \
    --model_name stanford-crfm/BioMedLM \
    --output runs/exp_001/eval_results.jsonl
```

For zero-shot evaluation (no fine-tuning), omit `--adapter_dir`.

Evaluation automatically detects each test record's modality and applies the matching metric:

| Modality | Metric |
|---|---|
| CRISPR | Classification accuracy, essential-class recall |
| scPerturb-seq DEA (list format) | Gene set overlap@k |
| scPerturb-seq DEA (pairwise format) | Direction accuracy, log2fc magnitude error |
| scPerturb-seq GSEA | Pathway name overlap (F1) |
| All modalities | ROUGE-L (text similarity, format-agnostic) |

`benchmark.py` contains the underlying metric functions (gene set overlap, direction accuracy, pathway enrichment) used by `evaluate.py`, and can be run standalone on a saved predictions file to rerun or compare metrics without regenerating predictions.

**Example evaluation output shape** (printed to the console when `evaluate.py` runs):

```
============================================================
EVALUATION RESULTS
============================================================
Model:        <model_name>
Adapter:      <adapter_dir>
Total test records: <n>
ROUGE-L mean: <rouge_l_mean>

CRISPR (<n_crispr> records):
  Accuracy: <accuracy> (<n_correct>/<n_crispr>)
  Unparseable: <n_unparseable> (<pct>%)

DEA (<n_dea> records):
  Mean overlap@k: <overlap_at_k>

GSEA (<n_gsea> records):
  Mean F1: <mean_f1>
============================================================
```

Per-record results (with the model's raw generated text alongside the true answer) are saved to the path given with `--output`, one JSON object per line.

## Training Record Format

Each record follows instruction-tuning format. The `instruction` and `input`
fields are what the model sees; `output` is what it's trained to generate;
`metadata` is excluded from training and used only for evaluation.

**CRISPR:**

```json
{
  "instruction": "What is the fitness effect of CRISPR-mediated inhibition of gene <gene> in <cell_line>?",
  "input": "Gene: <gene>. Cell line: <cell_line>.",
  "output": "<gene> is <essential|neutral|anti-essential> for survival of <cell_line> under <condition> conditions...",
  "metadata": {}
}
```

**scPerturb-seq DEA, list format:**

```json
{
  "instruction": "Predict the transcriptional response to CRISPR-mediated inhibition of gene <gene> in <cell_line>.",
  "input": "Gene: <gene>. Cell line: <cell_line>.",
  "output": "CRISPR-mediated inhibition of <gene> causes upregulation of: <gene_a> (<log2fc>), <gene_b> (<log2fc>); and downregulation of: <gene_c> (<log2fc>), <gene_d> (<log2fc>)...",
  "metadata": {}
}
```

**scPerturb-seq DEA, pairwise format:**

```json
{
  "instruction": "After CRISPR-mediated inhibition of gene <perturbed_gene> in <cell_line> under <condition>, what happens to gene <affected_gene>?",
  "input": "Perturbed gene: <perturbed_gene>. Affected gene: <affected_gene>. Cell line: <cell_line>.",
  "output": "After CRISPR-mediated inhibition of <perturbed_gene> in <cell_line>, gene <affected_gene> is <upregulated|downregulated> (log2fc = <value>).",
  "metadata": {}
}
```

**scPerturb-seq GSEA:**

```json
{
  "instruction": "What biological pathways are affected by CRISPR-mediated inhibition of gene <gene> in <cell_line>?",
  "input": "Gene: <gene>. Cell line: <cell_line>.",
  "output": "CRISPR-mediated inhibition of <gene> activates pathways: <pathway_a> (NES: <value>), <pathway_b> (NES: <value>). Suppressed pathways: <pathway_c> (NES: <value>).",
  "metadata": {}
}
```

## Datasets

### CRISPR screens

| Dataset | Cell line | Disease |
|---|---|---|
| biogrid_5 | K562 | CML |
| biogrid_2373 | SK-N-DZ | neuroblastoma |

### scPerturb-seq DEA / GSEA

| Dataset | Cell line | Disease | Perturbation type |
|---|---|---|---|
| nadig_2025_hepg2 | HepG2 | hepatoblastoma | CRISPRi |
| nadig_2025_jurkat | Jurkat | — | CRISPRi |
| replogle_2022_k562_gw_normalized | K562 | CML | CRISPRi (genome-wide) |
| replogle_2022_k562_essential_normalized | K562 | CML | CRISPRi (essential genes) |
| replogle_2022_rpe1_essential_normalized | RPE1 | — | CRISPRi (essential genes) |
| arce_2025 | primary CD4+ T cells (effector and regulatory) | healthy donor | CRISPRi |
| norman_2019_raw | K562 | — | CRISPRa (see note below) |

**Note on norman_2019_raw:** this is a legacy dataset not yet reprocessed by the Catalogue's current pipeline, and its `gene_symbol` field is frequently null for the perturbed-gene side. `generate_dea_pairwise.py` resolves the corresponding Ensembl gene ID via the Catalogue's `/v1/target/{ensembl_gene_id}` endpoint as a fallback; records that still can't be resolved are skipped.

### MAVE

Not yet included in this project's corpus. The Catalogue's current MAVE
datasets are from a yeast-model study (Weile et al., 4 human genes: UBE2I,
SUMO1, CALM2, TPK1). Deferred for now due to limited coverage rather than
excluded outright — a future iteration may incorporate MAVE data if broader
coverage becomes available in the Catalogue.

## Project Structure

- `catalogue_api_new.py` — Perturbation Catalogue API client (current; use this, not `catalogue_api.py`)
- `prepare_training_data_new.py` — fetch data from API and save as JSONL training records, list-format DEA (current; use this, not `prepare_training_data.py`)
- `generate_dea_pairwise.py` — fetch and save DEA training records in pairwise format (one record per gene-affected-gene pair)
- `subsample_pairwise_dea.py` — proportionally subsample a large pairwise DEA corpus across multiple dataset files
- `oversample_corpus.py` — duplicate essential-class CRISPR records before splitting, to address class imbalance
- `pipeline.py` — gene-level train/val/test split
- `split_with_pinned_crispr_gsea.py` — gene-level split that reuses a prior run's CRISPR/GSEA gene assignment, for fair cross-experiment comparison
- `finetune.py` — LoRA and QLoRA fine-tuning pipeline for BioMedLM
- `evaluate.py` — load a saved adapter (or run zero-shot) and evaluate on a test split, routing each modality to its matching metric
- `evaluate_pairwise_dea.py` — evaluation metrics for pairwise-format DEA records
- `benchmark.py` — evaluation metric functions used by `evaluate.py` (gene set overlap, direction accuracy, pathway name overlap)
- `add_task_prefix.py` — optionally prepend a modality tag (e.g. `[CRISPR]`) to instructions, for testing multi-task interference
- `requirements.txt` — all dependencies
